# 学生伏案写作业姿态检测系统项目需求文档

版本：V0.1
开发阶段：原型验证 / MVP
运行环境：Windows 10/11 + Python 3.11 + uv
核心任务：基于摄像头视频流，判断学生在写作业过程中是否存在过度低头、弯腰、长时间不良坐姿等情况，并进行本地提醒。

## 1. 项目背景

学生在写作业、阅读、书写等伏案学习场景中，容易出现长时间低头、身体前倾、弯腰、含胸等不良姿态。这类姿态如果持续时间较长，可能影响颈椎、脊柱、视距和学习习惯。

本项目拟通过普通摄像头或 RTSP 摄像头采集视频流，在本地设备上完成姿态检测与姿态判断，不依赖云端推理。系统优先关注边缘计算场景下的可落地性、实时性、低成本和隐私保护。

## 2. 项目目标

本项目第一阶段目标是开发一个可运行的姿态检测原型系统，实现以下能力：

1. 支持从 USB 摄像头、RTSP 摄像头或本地视频文件读取视频流。
2. 基于现成姿态估计模型提取人体关键点。
3. 判断学生是否存在过度低头。
4. 判断学生是否存在弯腰或上身明显前倾。
5. 对连续异常姿态进行时间窗口判断，避免单帧误报。
6. 在本地界面中显示检测结果、关键点骨架、角度数值和当前姿态状态。
7. 对异常姿态进行屏幕提醒或日志记录。
8. 原型阶段不保存原始视频，只保存角度、状态和事件日志。

## 3. 应用场景

### 3.1 家庭学习场景

学生在家中书桌前写作业，摄像头安装在书桌侧前方或显示器附近。系统实时判断学生是否出现长时间低头、弯腰等姿态，并通过屏幕或语音提醒。

### 3.2 教室或自习室场景

学生在固定座位上进行书写或阅读，系统可通过本地边缘设备或 Windows 电脑连接摄像头进行姿态检测。第一阶段只考虑单人检测，后续可扩展至多人检测。

### 3.3 产品原型验证场景

在没有嵌入式开发板的情况下，先使用 Windows 电脑和 RTSP 摄像头完成算法验证，确认摄像头角度、姿态判断规则和提醒逻辑，再迁移至 RK3588、N100 小主机、Jetson 或其他边缘设备。

## 4. 用户角色

### 4.1 学生

被检测对象。系统不需要学生主动操作，只需在摄像头视野范围内正常写作业或阅读。

### 4.2 家长或教师

查看检测结果、调整摄像头位置、设置提醒阈值和查看异常姿态统计。

### 4.3 开发与测试人员

负责算法调试、视频源接入、阈值校准、日志分析和后续边缘设备迁移。

## 5. 系统边界

第一阶段只实现单人、固定座位、固定摄像头位置下的姿态检测。系统暂不处理以下复杂情况：

1. 多人同时检测。
2. 学生频繁离开座位后的身份识别。
3. 医学级脊柱角度诊断。
4. 复杂遮挡条件下的高精度姿态恢复。
5. 云端账号系统、家长 App、长期健康报告。
6. 自动识别具体书写内容或学习行为质量。

系统定位为学习姿态提醒工具，检测结果用于行为提醒和数据参考，不作为医学诊断依据。

## 6. 功能需求

### 6.1 视频输入模块

系统应支持三类视频输入：

1. USB 摄像头输入，例如笔记本摄像头或外接 USB 摄像头。
2. RTSP 摄像头输入，例如网络摄像头、手机推流或局域网摄像头。
3. 本地视频文件输入，用于离线测试和算法回放。

视频输入模块应支持配置以下参数：

1. 视频源类型。
2. 摄像头编号或 RTSP 地址。
3. 分辨率。
4. 目标帧率。
5. 读取失败后的重连策略。
6. 是否显示原始画面。

推荐默认设置：

```yaml
video_source:
  type: "usb"
  camera_id: 0
  rtsp_url: ""
  width: 1280
  height: 720
  target_fps: 15
  reconnect: true
```

### 6.2 姿态估计模块

第一阶段推荐使用 MediaPipe Pose Landmarker 作为默认姿态估计模型。该模块负责从每一帧图像中提取人体关键点。

关键点重点关注：

1. 鼻子。
2. 左右耳。
3. 左右肩。
4. 左右髋。
5. 上半身关键点置信度。

如果使用 MediaPipe 33 点模型，系统应保留原始 33 点结果，并提取用于姿态分析的关键点集合。

姿态估计模块应输出：

1. 关键点坐标。
2. 每个关键点置信度。
3. 是否检测到有效人体。
4. 关键点是否满足后续分析条件。

### 6.3 头部低头检测模块

系统应根据头部关键点和上半身关键点判断低头程度。

第一阶段可使用以下简化规则：

1. 根据鼻子、耳朵、肩膀相对位置估计头部下倾趋势。
2. 如果接入 Face Landmarker，则优先使用头部 pitch 角判断低头。
3. 当头部下倾角度超过设定阈值并持续一段时间后，判定为低头异常。

建议初始阈值：

| 状态   | 判断条件                    |
| ---- | ----------------------- |
| 正常   | 头部下倾角小于 15°             |
| 轻度低头 | 头部下倾角大于 15°，但持续时间不足提醒阈值 |
| 明显低头 | 头部下倾角大于 25°，并持续超过 3 秒   |
| 严重低头 | 头部下倾角大于 35°，并持续超过 2 秒   |

阈值应支持配置文件修改。

### 6.4 弯腰 / 躯干前倾检测模块

系统应根据肩部中点和髋部中点估计上半身姿态。

计算方式：

1. 左右肩取平均，得到肩中点。
2. 左右髋取平均，得到髋中点。
3. 计算肩中点到髋中点形成的躯干向量。
4. 计算躯干向量与图像竖直方向或标定竖直方向之间的夹角。
5. 当躯干前倾角持续超过阈值时，判定为弯腰或身体过度前倾。

建议初始阈值：

| 状态   | 判断条件                  |
| ---- | --------------------- |
| 正常   | 躯干前倾角小于 15°           |
| 轻度前倾 | 躯干前倾角大于 15°           |
| 明显弯腰 | 躯干前倾角大于 25°，并持续超过 3 秒 |
| 严重弯腰 | 躯干前倾角大于 35°，并持续超过 2 秒 |

### 6.5 联合姿态风险判断

当低头和弯腰同时出现时，系统应判定为更高等级风险。

建议规则：

| 状态   | 判断条件         |
| ---- | ------------ |
| 正常   | 低头和弯腰均未超过阈值  |
| 低头风险 | 仅低头超过阈值      |
| 弯腰风险 | 仅弯腰超过阈值      |
| 联合风险 | 低头和弯腰同时超过阈值  |
| 严重风险 | 联合风险持续超过 5 秒 |

### 6.6 时间窗口与误报过滤

系统不应根据单帧结果直接报警。应采用滑动时间窗口进行判断。

建议规则：

1. 每帧计算低头角度和躯干前倾角。
2. 对角度进行滑动平均或指数平滑。
3. 只有连续超过阈值达到指定时间后才触发提醒。
4. 关键点置信度不足时，该帧不参与异常判断。
5. 学生短暂低头、转头、拿笔、翻书等动作不应立即触发异常提醒。

建议默认时间参数：

```yaml
posture_rule:
  smoothing_window_sec: 1.0
  warning_duration_sec: 3.0
  severe_duration_sec: 2.0
  cooldown_sec: 10.0
```

### 6.7 可视化模块

系统界面应显示以下内容：

1. 实时摄像头画面。
2. 人体关键点骨架。
3. 当前头部角度。
4. 当前躯干前倾角。
5. 当前姿态状态。
6. 异常持续时间。
7. 提醒状态。
8. 当前 FPS。

第一阶段可使用 OpenCV 窗口实现，不要求开发完整 GUI。

### 6.8 提醒模块

当系统检测到异常姿态持续超过设定时间后，应进行提醒。

第一阶段支持：

1. 屏幕文字提醒。
2. 控制台日志提醒。
3. 本地事件日志记录。

后续可扩展：

1. 语音提醒。
2. 蜂鸣器提醒。
3. 屏幕弹窗提醒。
4. 家长端统计报告。

提醒应具有冷却时间，避免连续重复提醒。

### 6.9 日志记录模块

系统应记录姿态检测过程中的关键事件。

建议日志字段：

1. 时间戳。
2. 视频源类型。
3. 是否检测到人体。
4. 头部低头角度。
5. 躯干前倾角。
6. 当前姿态状态。
7. 是否触发提醒。
8. 关键点置信度。
9. FPS。

日志格式建议使用 CSV 或 JSONL。

系统默认不保存原始视频，除非进入调试模式并由开发人员手动开启。

## 7. 非功能需求

### 7.1 实时性

在 Windows 开发环境下，系统应达到：

1. USB 摄像头输入：不低于 15 FPS。
2. RTSP 摄像头输入：不低于 10 FPS。
3. 单帧端到端处理延迟：尽量控制在 200 ms 内。
4. 姿态提醒允许存在 1–3 秒判断延迟，因为系统需要判断持续时间。

### 7.2 稳定性

系统应支持长时间运行，至少连续运行 30 分钟不崩溃。

RTSP 视频流断开时，应尝试自动重连。

当检测不到人体或关键点置信度不足时，系统应进入“无效检测”状态，而不应误判为异常姿态。

### 7.3 可配置性

以下参数应可通过配置文件修改：

1. 视频源。
2. 摄像头分辨率。
3. 检测帧率。
4. 低头角度阈值。
5. 弯腰角度阈值。
6. 持续时间阈值。
7. 提醒冷却时间。
8. 是否保存日志。
9. 是否显示骨架。
10. 是否开启调试模式。

### 7.4 隐私保护

系统第一阶段应遵循以下原则：

1. 默认不上传视频到云端。
2. 默认不保存原始视频。
3. 只保存关键点、角度、状态和事件日志。
4. 调试视频保存功能必须手动开启。
5. 后续产品化时，应提供隐私说明和数据清除机制。

### 7.5 可迁移性

代码结构应便于后续迁移至边缘设备。视频输入、姿态估计、姿态分析和提醒模块应解耦。

推荐模块结构：

```text
posture-detection/
├── main.py
├── config.yaml
├── requirements.txt
├── src/
│   ├── video_source.py
│   ├── pose_estimator.py
│   ├── posture_analyzer.py
│   ├── alert_system.py
│   ├── visualizer.py
│   └── logger.py
└── data/
    ├── logs/
    └── videos/
```

## 8. 技术路线

### 8.1 第一阶段推荐路线

第一阶段采用：

```text
Windows + Python 3.11 + uv
OpenCV 视频读取
MediaPipe Pose Landmarker 姿态估计
几何角度规则判断
滑动窗口过滤
OpenCV 可视化
CSV/JSONL 日志记录
```

该路线优先解决算法闭环问题，适合快速验证摄像头角度、姿态规则和提醒策略。

### 8.2 第二阶段增强路线

如果第一阶段存在误报，可增加轻量分类器。

输入特征：

1. 头部角度序列。
2. 躯干角度序列。
3. 关键点相对坐标。
4. 角度变化速度。
5. 关键点置信度。
6. 异常持续时间。

可选模型：

1. LightGBM。
2. XGBoost。
3. 1D-CNN。
4. TCN。
5. LSTM。

第二阶段不建议直接训练端到端图像分类模型。优先使用骨架和角度特征，便于解释和部署。

### 8.3 第三阶段边缘部署路线

如果后续迁移到边缘设备，可根据硬件选择：

| 硬件平台                     | 推荐推理方案                              |
| ------------------------ | ----------------------------------- |
| Windows / Intel N100     | MediaPipe / ONNX Runtime / OpenVINO |
| RK3588 / Orange Pi 5 Pro | RTMPose-t/s 导出 ONNX 后转 RKNN         |
| Jetson Orin Nano         | RTMPose-s/m + TensorRT              |
| Android                  | MediaPipe / MoveNet TFLite          |
| 树莓派 5                    | MediaPipe Lite / MoveNet Lightning  |

## 9. 算法判断逻辑

### 9.1 关键点定义

设：

```text
L_SHOULDER = 左肩
R_SHOULDER = 右肩
L_HIP = 左髋
R_HIP = 右髋
NOSE = 鼻子
L_EAR = 左耳
R_EAR = 右耳
```

肩中点：

```text
shoulder_center = (L_SHOULDER + R_SHOULDER) / 2
```

髋中点：

```text
hip_center = (L_HIP + R_HIP) / 2
```

头部代理点：

```text
head_center = NOSE 或 (L_EAR + R_EAR) / 2
```

### 9.2 躯干前倾角

```text
trunk_vector = shoulder_center - hip_center
trunk_angle = angle_between(trunk_vector, vertical_axis)
```

### 9.3 低头角

第一阶段可采用简化方案：

```text
neck_vector = head_center - shoulder_center
neck_angle = angle_between(neck_vector, trunk_vector)
```

如果加入 Face Landmarker，则使用头部 pitch 角作为低头判断主信号。

### 9.4 状态机

系统姿态状态分为：

1. `normal`：正常。
2. `head_down_warning`：低头风险。
3. `trunk_flex_warning`：弯腰风险。
4. `combined_warning`：低头和弯腰同时出现。
5. `severe_warning`：严重异常。
6. `invalid`：关键点不足或画面无效。

## 10. 验收标准

### 10.1 MVP 验收标准

第一阶段完成后，应满足以下标准：

1. 能够正常读取 USB 摄像头。
2. 能够正常读取 RTSP 视频流。
3. 能够在实时画面上显示人体关键点。
4. 能够实时输出头部角度和躯干角度。
5. 能够判断低头状态。
6. 能够判断弯腰状态。
7. 能够对连续异常姿态进行提醒。
8. 能够记录异常事件日志。
9. 系统连续运行 30 分钟不崩溃。
10. 在固定摄像头角度下，明显低头和明显弯腰能够被稳定识别。

### 10.2 测试样例

至少采集以下测试样例：

1. 正常写字 3 分钟。
2. 轻微低头写字 3 分钟。
3. 明显低头写字 3 分钟。
4. 身体前倾写字 3 分钟。
5. 低头 + 弯腰同时出现 3 分钟。
6. 翻书、拿笔、转头等干扰动作。
7. 摄像头光线较暗场景。
8. RTSP 网络轻微卡顿场景。

### 10.3 指标要求

建议使用以下指标评估：

| 指标           | 目标      |
| ------------ | ------- |
| 明显低头识别率      | ≥ 90%   |
| 明显弯腰识别率      | ≥ 85%   |
| 正常写字误报率      | ≤ 10%   |
| 单次提醒延迟       | 3–5 秒以内 |
| USB 摄像头 FPS  | ≥ 15    |
| RTSP 摄像头 FPS | ≥ 10    |
| 连续运行稳定性      | ≥ 30 分钟 |

## 11. 风险与应对

### 11.1 摄像头角度风险

如果摄像头正对学生，弯腰前倾角可能不明显。建议摄像头放置在学生侧前方 30°–45°，高度略高于桌面。

### 11.2 桌面遮挡风险

写作业时桌面可能遮挡髋部关键点，影响躯干角计算。可采用肩部、耳部、头部、背部轮廓等替代特征，或在后续版本中使用侧前方摄像头和 3D 姿态估计增强。

### 11.3 个体差异风险

不同学生身高、坐姿习惯、桌椅高度不同，统一阈值可能造成误报。系统应支持初始校准，让用户在正常坐姿下采集 5–10 秒基准姿态。

### 11.4 光照和图像质量风险

低光照、背光、摄像头模糊会降低关键点质量。系统应检查关键点置信度，并在质量不足时提示调整摄像头或光线。

### 11.5 RTSP 延迟风险

RTSP 视频流可能存在延迟和卡顿。姿态提醒任务允许一定延迟，但系统应使用真实时间戳计算持续时间，避免因帧率波动导致误判。

## 14. 总体结论

本项目第一阶段应优先完成本地姿态检测闭环。推荐采用 Windows + Python 3.11 + uv + OpenCV + MediaPipe Pose 的路线进行开发，通过现成模型提取人体关键点，再基于几何角度、持续时间和状态机判断低头与弯腰。

现成模型可以解决“人体关键点提取”问题，但最终的“是否过度低头、是否弯腰、是否需要提醒”需要结合具体摄像头位置、桌面场景和用户姿态数据进行规则设计与阈值校准。该路线成本低、开发快、便于解释，也方便后续迁移到 RK3588、N100、Jetson 等边缘计算设备。
